# 第一次学习：先检查数据，再运行模型

## 本次已经验证

输入来自官方仓库 `module2-irene-nowcasting/examples/sample_data.nc`。在固定上游版本下读取了文件，并执行配套Notebook；没有调用预训练模型。

- 变量：`RR`；维度顺序：`time, y, x`。
- 数据形状：`54 × 1400 × 1200`，`float32`。
- 时间范围：2025-08-28 21:55至2025-08-29 02:20（源时间戳未携带时区；不能仅凭本地系统时区转换）。
- 相邻帧相差5分钟。
- x坐标递增，y坐标递减，间距均为1000米。
- 文件包含大量NaN；NaN不应当成“观测到无降雨”。

## 发现的问题：单位尚未一致

这个样本中RR的单位属性写的是 `kg m-2 s-1`，而课程的数据介绍与IRENE模型说明按 `mm/h` 描述雨强。

仅从量纲看，1 kg m⁻²的液态水约等于1 mm水深；若每秒属性确实正确，换算到每小时应乘3600。但目前不能确认样本的数值是否已按每小时存储、只是保留了旧属性，因此不能直接乘3600，也不能静默当作mm/h。

本版保持原始数值，图例标注单位待核实。下一步应比较同一时刻云端数据及导出流程，确认数值与属性各自来源。解决前不报告物理单位下的预报误差、累计降水量或阈值降雨概率。这是待核实的元数据问题，不是已经确认的模型错误。

## 两个重要的实现细节

1. 时间窗口按帧数核对：xarray标签切片通常同时包含两端。在5分钟序列上，从T0减30分钟切到T0可能得到7帧；要取截至T0的6帧，可以先选择不晚于T0的记录，再取最后6帧，并检查时间间隔。
2. 输入窗口与未来观测分开：未来观测必须严格晚于最后一个输入时刻。以后划分训练/测试时，还应按完整降雨事件或时间段分组，避免重叠窗口泄漏。
